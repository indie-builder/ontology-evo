# 扩展销售分析口径

适用于 `config/analytics.json` 注册的 synthetic-analytics-v1 DuckDB样例，六张表均为合成数据，金额为人民币整数分。来源是项目生成器的明确设计，不代表真实生产口径。

`orders` 每行一订单，`order_items` 每行一个商品行，`refunds` 每行一次退款事件，客户和商品以各自ID关联，渠道投放每行一天一个渠道。

有效支付订单排除is_test，paid_date在所问期间，状态为paid、partially_refunded或refunded。按支付日期而不是创建日期归属期间，左闭右开。退款订单原来发生过支付，仍进入支付金额和订单数。

支付金额是有效支付订单原金额；成功退款限定这些订单、succeeded状态和快照截止前refunded_date；净收入是两者之差。季度问题默认截止下一季度首日，待处理和截止后退款不扣。该净额不是财务确认收入或当期净现金流。

支付客单价是支付金额除以订单数，购买客户数去重customer_id。客户地区和客户类型来自customers当前静态记录，未模拟历史维表变更。商品明细可用于品类支付金额，但退款没有商品分摊，因此不能声称得到准确的品类净收入。

渠道来自订单channel。channel_spend按spend_date和channel统计投放成本，应先各自聚合到一致粒度再比较。净收入除以投放成本是描述性回报比，不是ROI利润率，不证明因果归因；样例未包含全部经营成本。

生成数据的创建日期跨2025和2026年，支付存在延迟，退款可延迟35天。相对日期按当前系统日期解释，数据覆盖与查询结果仍需真实检查。Parquet按created_month分区，不保证支付日期过滤可以有效裁剪该分区。

新数据源应单独建立 `.evoontology/analytics` 本体与任务。原12单SQLite的 `.evoontology` 保留为独立示例，不能混用问题、映射、轨迹或固定答案。
